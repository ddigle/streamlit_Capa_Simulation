# 사내에서만 설치하는 패키지.
#
# `pyproject.toml` 에 적지 않는 이유: uv 락파일은 universal 이라 extra·group 을 가리지 않고
# **전부 해석한다.** `[project.optional-dependencies]` 에 두면 `--extra` 를 고르지 않아도
# 해석 대상이 되어, 사내 인덱스에 닿지 못하는 개발 PC 에서 `uv lock` 이 그 자리에서 죽는다
# (실제로 확인: `dns error … 알려진 호스트가 없습니다`).
#
# 이 파일로 빼면 `pyproject.toml` 과 `uv.lock` 이 **사내·사외에서 완전히 같아진다.** 그래서
# 배포 ZIP 에서 빼야 할 파일이 없고, 의존성을 바꿔도 ZIP 하나로 사내에 반영된다.
#
# 사내 설치 (전체 절차는 README.md 의 「초기 설정」):
#     uv sync
#     uv pip install -r requirements-company.txt
#
# 그 뒤로는 `uv sync --inexact` 를 쓴다 — 그냥 `uv sync` 는 락에 없는 이 패키지를 지운다.
# 패키지가 없어도 앱은 뜬다. 사내 조회 화면만 안내 문구를 띄우고 멈춘다.
#
# **C-DEP WebIDE 에서는 위 두 줄이 그대로 안 된다.** 이 계열 이미지는 두 가지를 미리 정해
# 두는데 둘 다 이 파일의 `--index-url` 을 무력화한다(사내에서 `uv -v` 로 원인까지 확인함).
#
#   1) 환경변수 `UV_DEFAULT_INDEX`(와 `PIP_INDEX_URL`)가 **공개 PyPI 미러**로 고정돼 있고,
#      이것이 `--index-url` 보다 먼저 이긴다. `bigdataquery` 는 사내 전용이라 공개 미러에
#      없으므로 자격증명이 맞아도 `not found in the package registry` 로 끝난다.
#   2) uv 는 제 내장 인증서만 믿어 사내 CA 를 모른다 — 서버에 닿아도
#      `invalid peer certificate: UnknownIssuer` 가 난다(`curl` 은 OS 인증서를 써서 통과한다).
#
# 그래서 WebIDE 에서는 **추가 인덱스로 넣고 시스템 인증서를 쓰게** 한다:
#
#     export UV_EXTRA_INDEX_URL="https://<AD 계정>:<Artifactory API 토큰>@artifactory.samsungds.net/repository/dataservice-devsecops-pypi/simple"
#     uv pip install bigdataquery==2.5.0 --system-certs
#
# 아래 `--index-url` 은 개발 PC 표기로 남겨 둔다 — WebIDE 에서는 위 환경변수가 이긴다.

--index-url https://artifactory.samsungds.net/repository/dataservice-devsecops-pypi/simple

bigdataquery==2.5.0
