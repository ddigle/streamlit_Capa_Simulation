# Capa Simulation

HBM·EDP-TSV PKG 라인의 월별 부하량, 대당 Capa, 소요대수, 확보율과 Bottleneck(B/N) 공정을 DuckDB 에 저장한
시나리오 기준정보로 계산하는 Streamlit 앱입니다. 화면 이름은 `S.PKG CAPA AX Management` 입니다.

- 새 웹 세션은 가장 최근에 지정한 **공식버전** 리비전을 불러옵니다.
- 웹에서 고친 계획·수율·Capa 기준정보는 그 브라우저 세션의 활성 시나리오에만 있고, 사이드바 `시나리오` 팝업에서
  저장해야 새 **리비전**(내용은 다시 고치지 않습니다 — 이름표인 리비전명만 고칠 수 있습니다)으로 남습니다. 저장하지
  않은 편집은 세션이 끝나면 사라집니다.
- **바꾼 것 없는 저장은 새 버전·리비전을 만들지 않고 「바뀐 것이 없습니다」 로 알립니다**(2026-11-01) — 사이드바 「신규
  리비전 저장」(편집 표·조회기간·공정 필터·가상 제품 이력이 그 시나리오 최신 리비전 그대로일 때 — 리비전명만 다른 것은 같은
  내용입니다. 옛 리비전을 불러와 그대로 저장해도 최신과 내용이 다르면 새 리비전입니다), Admin `Proc Rename`·`표시순서
  관리` 직접 편집, HOME Preference 저장 일곱(판정 기준·확보율 보정·공지·Top5 구간·주요공정 프리셋·선행 B/O·선행
  입고 실적 — 변경 메모만 적은 저장도 같습니다. 한 번도 저장하지 않은 칸의 첫 저장은 씁니다), 설비 시나리오 「이름
  바꾸기」·「리비전명 저장」.
- GitHub 에서 소스만 받은 빈 환경도 첫 실행에 DuckDB 스키마와 합성 `DEMO_*` 시나리오·리비전·공식버전을 스스로
  만들어 바로 뜹니다. 시나리오가 하나라도 있으면 이 시드는 아무것도 만들거나 덮어쓰지 않습니다.

개발 규칙과 파일별 책임은 [AGENTS.md](AGENTS.md), 확정사항과 작업 목록은 [docs/TODO.md](docs/TODO.md)에 있습니다.
문서 전체의 지도는 맨 아래 [문서 지도](#문서-지도)입니다.

## 무엇을 계산하나

```text
Core_Data (사내 BigDataQuery / 개발용 data/input/Core_Data.csv / 내장 합성 시드)
  → 78컬럼 검증 + pandas 로 RQ 16개 표 변환
  → data/capa_simulation.duckdb   시나리오 · 리비전(내용 불변) · 공식버전 · 공용 표시순서
  → 최신 공식버전 또는 고른 리비전 → 사용자별 활성 시나리오(세션)
  → 부하량 → 대당 Capa → 소요대수 → 확보율 → B/N 공정 → HOME 대시보드

data/equipment_availability.duckdb   공통 호기 대장(호기 정보 · 실적 · 상태 · 기존 보유대수)과 설비 시나리오 일정
                                     (날짜 · 시나리오 메모 · 비가동)의 불변 저장 이력 · 공식 지정
  → 세션의 설비 시나리오(새 세션 = 공식) → 주차별 가용대수 · 설비 일정 기준 가용대수 · Space 배치(그 시나리오의 배치)
```

계산의 뼈대는 아래와 같습니다. 정확한 규칙(Dummy 산식, 측정률 기본값, 제외 행, PKG Buffer 계수 등)은
`AGENTS.md` 6장이 정본입니다.

```text
부하량    PKG·Chip(Kea) · Wafer(매) · Density(억Gb) — PKG PLAN 에 수율·Chip 구성을 걸어 환산
대당 Capa = 환산_UPEH × 24 × 효율 ÷ 여유율 × 모듈수 × 가동일수 ÷ Lot측정률 ÷ WF측정률
환산_UPEH = UPEH(Main) · 60 ÷ ST(MI — ST 는 한 개당 분으로 입력), CHIP·PKG 는 다시 ÷ 1,000
소요대수  = 부하량 ÷ 대당 Capa        (RQ_REQB 의 Area·STEP·MCP 경로별로 나눈 뒤 공정으로 합산)
확보율    = 가용대수(RQ_EQP_AVBL) ÷ 소요대수
B/N       = 그 달 확보율이 가장 낮은 공정
```

확보율은 **확보·경고·부족** 셋으로 판정합니다. 기준(정수 %, 기본 110%·100%)은 시나리오와 무관한 공용 설정이고
`HOME 설정 → 판정 기준` 탭의 `확보율 판정 기준` 한 곳에서 정합니다. 달마다 다른 기준을 둘 수 있고, 확보율을 소수 첫째 자리에서
반올림한 정수 % 가 기준과 같거나 크면 확보입니다(110% 면 109.5% 도 확보 — 이렇게 겨우 든 공정의 기준 대비 여유는 0 으로
적습니다). 예전에 반 칸 낮춰 저장한 109.5%·99.5% 도 110%·100% 로 읽어 판정이 그대로입니다. 기준 칸(기본 두 칸 · 월별 표 ·
제약 시뮬레이션과 개조 일정의 기준 확보율)에 소수를 치면 사사오입한 정수로 읽고(109.5 → 110), 판정 기준은 **50 ~ 300%** 안이어야
저장됩니다 — 밖이면 저장하지 않고 저장 단추 아래에 어느 달 · 어느 칸인지 적습니다(제약 확보율과 같은 범위). 제약 시뮬레이션과
개조 일정의 기준 확보율 직접 입력 칸도 같은 50 ~ 300% 를 받아 HOME 설정 판정 기준에 저장한 기준을 그대로 칠 수 있습니다. 개조 일정이 기한을
못 맞추면 「기준 n% 낮추기」 의 n 은 기준 확보율 칸에 그대로 칠 정수 % 입니다(「HOME 기준」 에 월별 예외가 있으면 n 은 모든 달 기준을 n% 낮추는
폭이라, 칸에 한 값을 치면 기본보다 낮던 달의 기준이 올라가 들어가지 않을 수 있습니다).

### 세 영역

사이드바 계산 그룹은 차례대로 셋입니다. 실행 관리와 Dynamic Capa 사이에는 「생산 진도」 상자가 있습니다(2026-11-02 — 머리 화면과 하위 샘플 페이지 셋(2026-11-04, 임시) 모두 모듈 화면이 들어올 자리 하나).

| 그룹 | 뜻 |
|---|---|
| **Static Capa** | **약속.** 기술팀의 Capa 기준정보와 생산계획으로 낸 미래 Capa 와 부족 대수 |
| **실행 관리** | **이행.** 약속한 Capa 가 실제로 확보되는지 공정·기간·호기로 재고, 어긋난 곳을 추적 |
| 생산 진도 | 2026-11-02 에 실행 관리와 Dynamic Capa 사이에 세운 펼침 상자. 보일 내용은 모듈이 맡아(2026-11-03) 지금은 머리와 샘플 페이지 셋(2026-11-04, 임시) 모두 모듈 화면이 들어올 자리만 있음 |
| **Dynamic Capa** | **실적.** 실행 관리가 모은 실적으로 다시 낸 Capa 와 그것으로 하는 단기 운영(재공) |

말을 이렇게 가릅니다 — 「Dynamic」 은 실적 Capa 에만 씁니다. 설비 마스터 일정으로 낸 가용대수는 **설비 일정 기준
가용대수**(짧게 「일정 기준 가용」), HOME 에서 확보율에 % 를 손으로 더하고 빼는 입력은 **확보율 보정**입니다. 퍼센트 차이는 어느 화면이든 「%」 로 적고
퍼센트 포인트 기호(% 뒤 p)는 쓰지 않습니다(2026-11-01 사용자 결정).

## 초기 설정

`pyproject.toml` 과 `uv.lock` 은 양쪽이 완전히 같습니다. `uv sync` 가 `dev` 그룹(mypy·ruff·pytest)까지 함께 깝니다.

### 0단계. 준비물 확인

```powershell
git --version
py -3.10 --version     # 3.10.11 이 나와야 합니다
uv --version
```

`uv` 가 없으면 `pip install uv` 또는 [astral.sh/uv](https://docs.astral.sh/uv/) 안내를 따릅니다.

### 1~3단계. 받기 · 환경 만들기 · 확인

```powershell
git clone <저장소 주소> C:\dev\streamlit_project
cd C:\dev\streamlit_project
uv sync
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m streamlit run app.py --server.port 8501
```

- 배포 ZIP 으로 받았다면 `git clone` 대신 그 폴더에서 시작합니다. 첫 ZIP 은 손으로 풀고, 다음부터는
  `scripts/apply_deploy_package.py` 가 적용을 맡습니다(5단계).
- `.venv` 가 생긴 뒤의 명령은 `.\.venv\Scripts\python.exe ...` 로 칩니다. **사내에서는 `uv run --no-sync python ...`**
  을 씁니다 — 맨 `uv run` 은 돌기 전에 락을 다시 맞추며 빠진 패키지를 까는데, `--no-sync` 는 그 일을 아예 하지 않아
  사내 전용 패키지를 건드리지 않습니다.
- 빈 `data/` 에서도 앱이 뜹니다. Excel·Core Data CSV·사내 DB 없이 HOME 과 계산 페이지를 열 수 있습니다.

### 4단계. 사내 전용 패키지 넣기 (사내만)

```powershell
uv pip install -r requirements-company.txt
```

- `bigdataquery` 를 사내 Artifactory 인덱스에서 받습니다. 인덱스 주소는 그 파일 안에 있습니다.
- C-DEP WebIDE 처럼 이미지가 `UV_DEFAULT_INDEX` 를 고정해 둔 곳에서는 위 한 줄이 그대로 안 됩니다. 추가 인덱스와
  시스템 인증서로 까는 법, 로그인·요청자 계정 설정은 `docs/bigdataquery_webide_setup.md`.
- **이 뒤로는 `uv sync` 대신 `uv sync --inexact` 를 씁니다.** 맨 `uv sync` 는 락에 없는 패키지(`bigdataquery`)를
  지웁니다. 지웠으면 위 명령을 다시 돌립니다.
- `bigdataquery` 가 pandas · numpy 판의 위 끝을 두므로 `pyproject.toml` 이 같은 범위로 묶습니다(`requirements-company.txt` 머리). 맞는지는
  `uv pip check` 로 봅니다.
- `bigdataquery` 를 `pyproject.toml` 에 적지 않는 까닭은 `requirements-company.txt` 머리에 있습니다 — 락은 모든
  extra·group 을 해석하므로 사내 인덱스에 닿지 못하는 개발 PC 에서 `uv lock` 이 죽습니다. 덕분에 배포 ZIP 에서
  빼야 할 파일이 없습니다.
- 패키지가 없어도 앱은 뜹니다. 시나리오 관리 `DB 등록` 탭만 안내를 띄우고 멈춥니다.
- C-DEP CD(배포 서버)에는 셸이 없어 위 명령을 칠 수 없습니다. 배포 설정의 환경변수 표에 값을 넣으면 이미지의 시작
  스크립트(`scripts/container_start.py`)가 설치·로그인 토큰을 갖추고 결과를 Admin Area 「서버 시작 점검」에 남깁니다 —
  넣을 key 는 `docs/bigdataquery_webide_setup.md` 「C-DEP CD(배포 서버)」.
- C-DEP CD 서버는 디스크가 CI/CD 때 사라집니다. `CAPA_S3_SYNC_MODE=managed` 면 두 DB 의 정본이 운영 버킷에 있고 시작 스크립트가
  받은 뒤에만 앱을 띄웁니다 — 받는 동안은 같은 포트에서 「데이터 받는 중」 만 보입니다. 저장은 앱이 1분 안에 모아 올립니다
  — 이관 · 환경변수 · 복구는 `docs/objectstore_setup.md`.
- C-DEP CD 서버는 통합인증(SSO)으로 로그인한 사람만 들어오게 할 수 있습니다 — 시작 스크립트가 진입 파일
  `capa_server.py`(`app.py` 를 감싸 콜백 경로·문지기를 붙인 것)로 앱을 띄우고, 환경변수 표의 `ADFS_CLIENT_ID` 가 켜는
  스위치입니다(비면 지금처럼 열림). 로그인은 마지막 사용 뒤 6시간 유지되고 앱을 쓰는 동안 저절로 늘어납니다(최대 24시간 —
  `CAPA_SSO_SESSION_HOURS` · `CAPA_SSO_SESSION_MAX_HOURS`). 운영에서는 접속 명단(`CAPA_ACCESS_ADMINS` 필수 · `CAPA_ACCESS_USERS`, S3 키를 넣으면 사용자는 S3 파일에서 재시작 없이 Admin 으로 넣고 뺍니다)에 있는 사람만 들어옵니다 — 없는 사람은 로그인해도 거절 화면을

위 14개는 웹에서 고치고 리비전으로 저장하는 표, 아래 둘은 데이터셋에 붙은 참조 표입니다. 표마다의 키와 저장

### 설비 시나리오

설비 마스터는 **공통 호기 대장**과 **설비 시나리오 일정**으로 나뉩니다(설비 마이그레이션 `0027`, 2026-10-24 결정).
호기 정보·Space 좌표(공식 배치)·실적·상태·이력·메모·기존 보유대수는 시나리오와 무관하게 늘 최신 하나이고, 날짜 여섯(제진대·물류·
반입·Qual·정지·반출/이설)과 `시나리오 메모`, 비가동 일정 전체가 시나리오마다 따로입니다 — 예를 들어 「운영 일정」 과
「셋업 실무」 일정을 나눠 둡니다. 가정 설비 시나리오는 공식과 다른 배치(가정 배치)도 따로 듭니다(아래 「가정 설비 시나리오의
Space 배치」). 설비 시나리오는 Capa 시나리오와 짝짓지 않고 HOME·Static 확보율(`RQ_EQP_AVBL`)
계산에 들지 않습니다.

- 시뮬레이션처럼 **공식 지정**(append-only)으로 운영합니다. 새 세션·HOME 칸에서 들어온 공정 Capa 상세·진척
  비교 기준선은 공식이고, 가용설비 현황·필요 단축 일정·공정 Capa 상세·제약 시뮬레이션·Space 현황은 사이드바 「설비 시나리오」
  줄에서 고른 시나리오를 따릅니다. 시나리오 만들기는 복제로만(「여기서 새 시나리오」 — 어느 리비전에서든), 이름 바꾸기·지정은
  시나리오 관리 › 설비 시나리오 탭입니다.
- 같은 탭에서 일정 리비전마다 **리비전명**(나중에 고칠 수 있는 이름표 — 내용은 그대로)을 붙이고, 옛 리비전을 골라 **「이
  리비전으로 되돌리기」** 를 합니다. 되돌리기는 옛 리비전을 고치지 않고 그 일정(날짜 여섯·시나리오 메모·비가동)을 같은
  시나리오의 새 리비전으로 다시 저장합니다 — 공통 대장은 그대로이고, 그 리비전 뒤에 공통 대장에 든 호기는 그 리비전에 일정이
  없어 「일정 없음」 이 됩니다. 확인 글이 바뀌는 호기 수와 「일정 없음」 이 되는 호기 수를 먼저 보이고, 확인 체크는 그 글에
  묶여 다른 리비전을 고르거나 그 사이 누가 저장·지정하면 풀립니다. 공식 시나리오에서 되돌리면 저장과 같은 공식 지정 규칙(기본
  켬)이 걸립니다. 리비전명은 40자까지입니다. 지금 이름 그대로 「리비전명 저장」·「이름 바꾸기」 를 누르면 「바뀐 것이
  없습니다」 만 알립니다.
- 시나리오 관리 › 설비 시나리오의 리비전 표와 리비전 상자, 설비 마스터 탭 저장 이력(표·「조회 리비전」 상자)은 리비전을
  **전부** 싣습니다 — 표는 스크롤하고 오른쪽 위 도구 막대로 찾고, 상자는 글을 쳐서 찾습니다(2026-11-01 결정). 구획 표 아래 한
  줄이 늘 전체 수와 출처별 수를 적습니다(「전체 82줄(이관 70 · 저장 12)」). 한 줄씩 긴 **사이드바 설비 시나리오 팝업 라디오만
  최근 50개**이고, 넘으면 「최근 50개 · 전체 82개 — 더 옛 32개는 시나리오 관리 › 설비 시나리오에서 고릅니다.」 를 적습니다.
  저장 이력 아래 펼침 「공통 대장 저장 이력」(공통 칸만 바꾼 저장도 저장자·메모로 찾는 곳)은 최신 50개까지이고, 더 옛 공통
  리비전이 있으면 머리를 「최근 50건(r31~r80)」 꼴로 적습니다(리비전 표의 「공통 rN」 칸은 그 밖의 공통도 번호를 적습니다).

  새 비가동은 기본으로 다른 시나리오에도 같은 일정으로 들어가고, 공식 시나리오에 새 일정 리비전이 생기는 저장은 기본으로
  공식 지정까지 합니다. 그 시나리오에 일정이 없는 호기는 그 시나리오 계산에 들지 않습니다(「일정 없음 n대」). 가정 설비

오른쪽 아래 알림창과 머리 `Alarm` 으로 알립니다(2026-11-04 — 내용이 바뀔 때만 뜸). 도면은
가로 세 칸입니다 — **왼쪽 칸**(머리 줄에 서던 범례가 여기로 왔습니다 — 층 보기는 범례, 배치 편집은 범례·도면 요소·선택·서식·격자·캔버스 묶음) · 도면 · **오른쪽 미배치
칸**(층 배치 편집 — 도면을 가리지 않는 옆 칸, 넓히면 칩 두 열, 도면의 호기를 끌어 놓으면 미배치로). 두 칸은 칸막이로 폭을 끌고 접으며
그 폭·접힘을 이 브라우저가 기억합니다(접으면 도면 위 가장자리에 단추만 뜹니다 · 편집기 폭 900px 아래에서는 도면 위 겹침 서랍). 도구 줄 **「단축키」** 는 지금 화면에서 쓸 수 있는 키를 「키조합 : 기능」 으로 보입니다. 도구 줄 **「화면 고정」** 을 켜면 도면이 화면 탭 줄 바로
아래로 올라와 창 높이에 맞고 페이지가 굴러가지 않습니다(휠은 도면 이동, Ctrl+휠 확대 — 층·FAB 를 바꾸거나 편집을 켜고 끄거나 다른
화면에 다녀오면 풀림). 자세한 것은 Guide(`guides/space_status.md`).

층 도면 요소에 **베이**(왼쪽으로 누운 U자 화살표 — 가운데 늘 「B<번호>」, 「80」·「B80」 모두 「B80」)를 넣고, 동선·베이는 엑셀처럼
**머리 크기**(너비·길이 3×3)·선 색·굵기·선 모양을 고릅니다(여럿 골라 한 번에). 저장은 설비 마이그레이션 `0033` 의 요소 모양 값 칸
(`look_json` — 층·FAB 요소와 가정 배치 차이)이고 옛 요소는 지금 모습 그대로입니다. 도면에 붙은 글자(요소 이름표·글자·층 블록 글·
호기 이름·Main 설비명)는 **확대·축소를 따라 커지고 작아집니다**(고른 글자 크기 = 도면 1칸이 화면 8px 일 때, 위 2배, 화면 6px 아래는 숨김 —
호기 이름·Main 설비명은 7px — 저장값은 그대로). `0033` 을 실은 배포부터는 그 앞 ZIP 으로 되돌리지 않습니다(런북 4-2).

층·FAB 도면 요소에 **도형** 아홉 가지(사각형·원·ㄴ자 박스·ㄷ자 박스·테·삼각형·마름모·십자·블록 화살표)를 넣습니다. 엑셀
도형처럼 노란 **모양 조절 손잡이**(둥글기·팔 두께·꼭짓점 자리 등 — 두께는 짧은 변 기준이고 손잡이·칸으로 크기를 바꿔도 그린 두께를
지켜 ㄴ자의 어느 팔을 늘여도 그 팔 길이만 늘고, 두께는 그 방향 길이까지 굵게 할 수 있음)·Shift 비율 유지(두께도 함께 커짐)·돌리기·뒤집기(이름표 칸 바로 밑 한 줄 · `Shift+H`/`Shift+V` · 여럿 한 번에), 채우기 색·투명도·선 색·굵기·
선 모양·빗금·이름표, **도형 바꾸기**(크기·서식 유지)를 고릅니다. 도형은 꾸밈이라 호기 아래에 그리고 겹침 경고에 들지 않습니다.
저장은 같은 `look_json`(프리셋·모양 조절·투명도·선)과 요소 색 칸이라 마이그레이션이 더 없습니다.

배치 편집에서 **서식 복사·붙여넣기**를 엑셀처럼 씁니다 — `Alt+Shift+C`(Mac `⌥+⇧+C`)는 고른 것(마지막으로 누른 것)의 서식을 담고
`Alt+Shift+V` 는 지금 고른 것 모두에 붙입니다. `Ctrl+Shift+C/V` 도 받지만 Chrome 은 `Ctrl+Shift+C` 를 개발자 도구(검사)로 먼저 가져갈
수 있고, Windows 에서 `Alt+Shift` 로 입력 언어가 바뀌면 `Ctrl+Shift+C/V` 나 붓 단추를 씁니다. 왼쪽 칸 **「서식」** 의 붓은 한 번
누르면 다음에 누른 것 하나에, 두 번 누르면 잠가 누를 때마다 붙입니다(빈 곳을 끌면 그 안 전부 · Esc 끝). 서식은 크기(같은 종류끼리
— 호기는 호기끼리·Main 설비 묶음끼리)·색·선(면 색·투명도·선 색·굵기·모양·화살표 머리 크기·빗금 — 받는 쪽에 있는 칸만)·글자(크기·
색·영역 정렬)이고 체크로 고릅니다. 자리·이름표 글·회전·도형 꼴은 옮기지 않고, 호기의 면 색은 계산 값이라 호기에는 크기만 붙습니다.
붙이기 한 번이 실행 취소 한 번이고 담은 서식은 이 브라우저 탭 안에서 층·FAB 를 오가도 남습니다(저장·마이그레이션 없음 — 붙인 결과만
지금처럼 적용·저장).

층 상세 도면 아래에 있던 호기 표(21칸)는 도면 위 **「호기 정보」 창**으로 옮겼습니다(도구 줄 「호기 정보」 또는 호기를 두 번 눌러 엶 —
층 보기·배치 편집 모두). 창은 끌어 옮기고 귀퉁이로 크기를 바꾸며 접고 닫습니다(자리·크기는 이 브라우저가 기억). **고른 호기** 탭은
도면에서 고른 호기의 칸(모듈이면 그 Main 설비 줄 전부, 편집에서 여럿 고르면 여러 줄), **필터** 탭은 칸 머리 ▾ 로 엑셀 자동 필터처럼
값을 골라(칸 안 또는 · 칸끼리 그리고 · 날짜·숫자 범위) 맞는 호기 목록을 보이고 그 호기를 도면에서 남보라 테로 강조합니다(나머지는
흐림, 편집에서는 미배치 칸 칩도). 목록 줄을 누르면 그 호기로 갑니다(300% 까지 확대). 읽기만이고 새 DB 읽기는 없습니다. 층 CSV 도
창 제목 줄 `CSV` 안입니다 — 「도면에 선 호기 · 모든 칸」(옛 도면 아래 내려받기와 같은 파일) · 「보이는 줄」(지금 탭의 줄, 창의 칸), 도면 아래에는
아무것도 없습니다. 층 보기에서 호기를 누를 때 서버로 보내는 것은 색 기준 「필요 단축」 을 켠 동안뿐입니다(그 칸의 누른 호기
상세 — 다른 때는 누를 때마다 화면이 다시 돌지 않습니다).

### Space 층 사용 상태

Space 현황 FAB 전체 아래 층 목록 표의 `사용 편집` 에서 층마다 「사용」 또는 「비활성」 을 고르고 비활성 사유를 20자까지
직접 적습니다(비우고 끄면 「사용 안 함」, 2026-10-26 결정 — 마이그레이션 없음) — 동 머리로 그 동 6개 층을 한꺼번에 「사용 안
함」·「생산라인 아님」 으로 바꿀 수 있습니다(설비 마이그레이션 `0029`, 2026-10-24 결정). 사유는 적은 글 그대로 보이고 FAB
도면 블록에서는 길면 「…」 로 줄입니다. 모두에게 같은 공용 설정이고 설비 시나리오와 상관없습니다. 비활성 층은 FAB
도면에서 회색 빗금으로 흐려져 눌러도
열리지 않고, 층 목록 맨 아래 접힌 「비활성 층 n개」 에서 열어 봅니다. 층 바로 가기·배치 편집기 「다른 층으로 보내기」·
가용설비 현황 설비 마스터 탭의 동·층 칸 선택지에서 빠지지만 **설비 마스터의 동·층 값과 저장 검사는 그대로**입니다 — 호기가 남은 층을 끄면 확인만
받고, 그 호기는 Space 목록·도면에서만 숨습니다.

### 입력 비가동 대수

가용설비 현황 셋째 탭 `Preference` 에서 호기에 잇지 않는 비가동을 **공정 × 달(생산월)** 대수로 넣습니다(환산 대수, 소수 가능,
빈칸 = 0 — 설비 마이그레이션 `0032`, 2026-10-27 결정). 행은 지금 설비 시나리오 저장본의 공정, 열은 사이드바 조회기간의 달이고
「입력 비가동 저장」 은 저장자·메모·이력을 남기며 다른 사람이 먼저 저장했으면 거부합니다. 모든 설비 시나리오가 같이 쓰는 공용
설정이라 가정 설비 시나리오를 보는 동안은 잠깁니다. 넣은 대수는 호기별 비가동과 별도 손실로 **설비 일정 기준 가용대수**(실행
관리)에서 더 빠집니다 — 공정 Capa 상세 ②·④(첫 줄 「월별 비가동 대수(입력)」)·필요 단축 일정·제약 시뮬레이션·Space 필요 단축
보기·가용설비 현황 `Summary` › `Static 대비 일정`(그림·시트의 설비 일정 기준 대여(비가동)·가용·확보율 교차검증)이 함께 바뀌고,
그 달 가용보다 크면 가용은 0 에서 멈춥니다. HOME·Static 의 기준정보 가용, 표준 목표·표준 대비 재공의 주차별 가용, Summary ›
Main(호기 상태)은 그대로입니다. 표는 폼이라 저장하기 전에 다른 화면으로 옮기거나 그 사이 다른 사람이 저장하면 적은 칸은
버려지고 최신 저장본이 섭니다.

공정 Capa 상세 ② 의 `비가동 영향` 줄(전월 대비 바로 아래)은 달마다 비가동이 깎은 가용과 그만큼의 확보율 차이를 함께
보입니다(예 「−1.8대 · −4.2%」 — 대수 아래 줄에 %). 깎은 가용은 호기별 비가동(비가동이 없었다면 가용이었을 몫) + 위 입력
비가동 가운데 실제로 뺀 몫(0 에서 멈춘 뒤)이고, 아래 줄 % 는 그 대수 ÷ 소요입니다(단축 전 설비 일정 기준 가용·소요). 깎은 것이 없으면
빈칸, 소요 0 이면 대수만입니다.
