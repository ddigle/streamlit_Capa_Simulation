# 사내·사외 두 환경 운영 절차

이 저장소는 **두 곳에서 열린다**. 사외(개발 PC)와 사내(WebIDE). 양쪽 모두 Claude Code 를
쓰지만 **역할이 다르고, 코드를 고칠 수 있는 곳은 한 곳뿐이다.**

지금 어느 쪽인지는 원격 주소로 가른다.

```powershell
git remote -v      # github.com 이면 사외, 사내 GitHub 주소면 사내
```

---

## 0. 원칙 — 정본이 둘로 갈리지 않게

| | 정본이 있는 곳 |
|---|---|
| **코드** | 사외 (`origin/main`) |
| **데이터** | 사내 (S3 스냅샷 · `data/` 실데이터) |

이 선을 흐리지 않는 것이 이 문서의 전부다. 사내 DuckDB 를 밖으로 가져오지 않듯,
**사내에서 만든 코드는 정본이 되지 않는다.**

작성자를 한쪽으로 몰아 둔 것은 취향이 아니라 설계다. 양쪽이 같은 파일을 고치기 시작하면
합칠 방법이 없다 — 두 저장소는 서로의 원격을 볼 수 없다.

---

## 1. 역할 분담

| | 사외 (개발 PC) | 사내 (WebIDE) |
|---|---|---|
| **하는 일** | 구현 · 리팩토링 · 테스트 작성 · 문서 | 진단 · 재현 · 검증 |
| **왜 거기서** | 사용량 여유, 합성 데이터로 충분 | **실데이터가 여기에만 있다** |
| **산출물** | 커밋 · 배포 ZIP | `review/` 아래 md |

사내 에이전트가 제일 잘할 수 있는 일은 **밖에서 못 하는 일**이다 — 실데이터로 돌려 보고,
오류 원문을 읽고, 실제 값의 분포를 확인하고, 재현 조건을 좁히는 것. 「고쳐라」가 아니라
**「무엇을 왜 고쳐야 하는지 밖이 재현할 수 있게 적어라」** 가 사내의 일이다.

### 사내 에이전트가 지킬 것 (하드 룰)

- **소스를 고치지 않는다.** `app.py`·`app_pages/`·`src/`·`tests/`·`scripts/`·`config/` ·
  루트 문서 — 어느 것도 편집하지 않는다.
- **쓸 수 있는 곳은 `review/` 뿐이다.**
- 배포 적용은 **손으로 하지 않고 스크립트를 실행**한다(§3).
- 고쳐야 할 것은 **코드가 아니라 문서로** 낸다. 제안 코드는 md 안 코드블록에 적는다 —
  그것은 저장소 수정이 아니다.

---

## 2. 절차

| 단계 | 어디서 | 무엇을 | 사람이 하는 일 |
|---|---|---|---|
| 1 | 사외 | 개발 · 커밋 | — |
| 2 | 사외 | 배포 ZIP 생성 · 메일 발송 | 발송 확인 |
| 3 | 사내 | ZIP 적용 → `deploy:` 커밋 | **ZIP 내려받기만** |
| 4 | 사내 | 실데이터로 조사 | — |
| 5 | 사내 | `review/` md 작성 → 푸시 | — |
| 6 | 사외 | md 를 근거로 다음 개발 | md 를 사외로 옮겨 전달 |

사람이 개입하는 곳은 **2번의 발송 확인**과 **3번의 ZIP 내려받기**, 그리고 **6번의 md 전달**
세 군데뿐이다. 6번은 md 를 대화창에 그대로 붙여넣으면 된다 — 그래서 리뷰 md 는
**그 자체로 완결**돼야 한다(§4).

---

## 3. 배포 적용 (3단계)

**덮어쓰기가 아니라 「지우고 풀기」다.** 덮어쓰기는 파일을 더하고 바꿀 뿐 **지우지 않는다.**
사외에서 지운 모듈이 사내에 남으면, 트리를 훑는 검사(`test_documentation_inventory` ·
`test_source_metadata`)가 **사내에서만** 깨진다. 그러면 사내가 그것을 진짜 결함으로 보고
리뷰에 적고, 사외에서는 재현되지 않는다.

```powershell
uv run python scripts\apply_deploy_package.py <내려받은 ZIP 경로>
```

이 스크립트가 하는 일:

1. 작업트리가 깨끗한지 확인한다 — **더러우면 멈춘다**(미저장 변경을 지우지 않기 위해).
2. ZIP 의 `DEPLOY_MANIFEST.json` 에서 출처 커밋을 읽어 **사내 HEAD 의 후손인지** 본다.
   아니면 멈추고 무엇이 덮일지 보여 준다.
3. 추적 파일을 지우고 ZIP 을 푼다. `review/` 는 남긴다.
4. 매니페스트의 해시로 **전 파일을 대조**한다.
5. `deploy: <SHA>` 로 커밋한다.

> **`git clean` 에 `-x` 를 붙이지 않는다.** `-x` 는 gitignore 된 파일까지 지우고, 거기에는
> **사내 DuckDB 와 `data/input` 실데이터**가 들어 있다. 한 글자 차이로 사내 데이터가 날아간다.
> 스크립트는 `-x` 없이 돌며, 손으로 할 때도 마찬가지다.

커밋은 **둘로 나눈다** — 3단계에서 `deploy:`(받은 것 그대로), 5단계에서 `review:`(판단한 것).
「무엇을 받았나」와 「무엇을 알아냈나」가 갈려야 나중에 되짚을 수 있다.

---

## 4. 리뷰 문서 (5단계)

경로는 `review/<ZIP 파일명>.md` — 예: `review/202609161506.md`. 이름만으로 어느 배포를 본
리뷰인지 확정된다. **`review/` 는 사내에만 있는 폴더다.** 사외에 만들면 ZIP 에 실려
되돌아와 사내 기록을 덮는다.

### 실데이터를 적지 않는다

이 문서는 **사내에서 사외로 나가는 유일한 것**이다. 그런데 성격상 실데이터로 채워지기 쉽다 —
실제 Pack Code, 공정명, 호기 ID, 로그 원문. `CLAUDE.md` 가 코드에 금지한 바로 그 값들이
검사 없이 나가게 된다.

**값의 「꼴」은 남기고 식별자는 가명으로 쓴다.** 표기 형식 자체가 논점일 때만 그 형식을 남긴다.

- 좋음 — 「`Pack Code` 에 `4.00E+02` 꼴(지수 표기)인 값이 2종, 5행」
- 나쁨 — 실제 Pack Code 값을 그대로 적는 것

### 양식

```markdown
# 리뷰 — <ZIP 파일명>

- 배포 커밋 : <DEPLOY_MANIFEST.json 의 SHA>
- 적용 일시 : <YYYY-MM-DD HH:MM KST>
- 리뷰 일시 : <YYYY-MM-DD HH:MM KST>
- 실데이터 식별값 포함 없음 : 확인함 ☐

## 1. 이번 배포에서 본 것
<변경 파일 목록을 따라가며 실데이터로 확인한 결과. 이상 없으면 없다고 적는다.>

## 2. 발견
### <제목>
- **증상** :
- **재현** : <사외에서 그대로 따라 할 수 있게>
- **관측** : <값의 꼴 · 건수 · 오류 원문. 식별자는 가명>
- **범위** : <몇 행 / 어느 화면 / 언제부터>

## 3. 제안
<수정 방향. 확신이 없으면 없다고 적는다 — 추측을 사실처럼 적지 않는다.>

```python
# 실패를 고정하는 테스트 (제안). 여기 적는 것은 저장소 수정이 아니다.
```

## 4. 사외에서 해야 할 일
<우선순위대로. 사내에서 할 수 있는 일과 갈라 적는다.>
```

---

## 5. 응급 상황

사내에서 당장 고쳐야 하는 날은 온다. 규칙에 없으면 그날 규칙이 조용히 깨지므로 미리 정한다.

- `hotfix/<날짜>` 브랜치에서만 고친다. `main` 에 직접 커밋하지 않는다.
- 리뷰 md 에 **「밖에서 반드시 재구현」** 으로 남긴다.
- 사외에서 재구현한 ZIP 이 들어오면 그 브랜치를 **버린다.**

사내 수정은 어떤 경우에도 정본이 되지 않는다.

---

## 6. 아직 없는 것

이 문서는 절차를 먼저 적었다. 아래는 **만들어야 하는 것**이고, 생기기 전까지는 그 단계를
사람이 손으로 한다.

| 필요한 것 | 어디에 | 상태 |
|---|---|---|
| `DEPLOY_MANIFEST.json` 생성 · 배포 태그 | `scripts/build_deploy_package.py` | 없음 |
| 변경 파일 목록(`git diff --name-status`) 동봉 | 같은 스크립트 | 없음 |
| `apply_deploy_package.py` | `scripts/` | 없음 |
| 사내 쓰기 차단 설정 | 사내 `.claude/settings.json` | 없음 |

`apply_deploy_package.py` 는 **사내에서 도는 물건인데 사외에서 만든다.** 처음 한 번은 사람이
사내에 옮겨 두어야 하고, 그 뒤로는 ZIP 에 실려 스스로 갱신된다.
