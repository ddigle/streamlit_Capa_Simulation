# 화면 설계 · 검수 규칙

마지막 갱신일: 2026-11-04 · 판 v1

## 1. 이 문서

화면을 만들거나 바꾸거나 검수할 때 대 보는 규칙의 정본이다. 2026-09 ~ 11 의 검수 의견 · 결정 보드 답 · 기존 규칙
(AGENTS · design_system)에서 되풀이된 꼴을 뽑아(귀납) 규칙으로 올렸고, 근거가 한 사례뿐이거나 서로 맞서던 18 물음은
2026-11-04 설계 규칙 확인 보드에서 사용자가 답했다(6장). 앞으로 화면 검수는 사람이 칸마다 보는 대신 이 규칙으로 하고,
사람은 규칙 밖 · 애매 · 되돌리기 어려운 화면만 본다(PRC-07).

규칙 77 — MUST 44 · SHOULD 33 · MAY 0, 묶음 열하나(3장). 상태는 모두 확정이다.

### 1-1. 정본 관계

| 문서 | 정하는 것 |
|---|---|
| 이 문서 | 화면에 무엇을 · 어디에 · 어떤 꼴로 두는가, 검수 때 무엇으로 통과 · 위반을 가르는가(규칙 · 수준 · 판단 질문 · 결정 기록) |
| `AGENTS.md` 8 · 9장 | 그 꼴을 어떤 함수 · 위젯 · key · 토큰 · 등록부 코드로 짓고 어떤 시험이 지키는가(구현 규칙) |
| `docs/design_system.md` | 색 · 서체 · 면 · 치수 토큰과 그 까닭 |
| `docs/module_guide.md` 5장 | 모듈 화면에 걸리는 몫 — 담당자 에이전트는 지침서만 읽으므로 거기에 옮겨 둔다 |

겹치면 이렇게 가른다 — 화면 판정(두는가 · 어디에 · 예외인가)은 이 문서가, 구현 방법(함수 이름 · 등록부 코드 · 허용 목록 ·
시험)은 AGENTS 가 정한다. AGENTS 8 · 9장에만 있는 구현 규칙(마크다운 막기 · 위젯 상태 · 편집표 구현 등)은 여기에 다시 적지
않고 설계 검토에서 다시 묻지 않는다(7-4). 두 문서가 어긋나면 같은 변경에서 둘 다 고치고, 고치기 전까지는 더 최근의 사용자
결정이 이긴다(PRC-08). 지침서 5장이 이 문서와 어긋나면 이 문서를 따라 5장을 고친다.

### 1-2. 읽는 법

- **수준**(RFC 2119 꼴) — MUST = 반드시, SHOULD = 권장(어기면 커밋 · 보고에 까닭을 적는다), MAY = 써도 되는 꼴(이 판에는
  없다). MUST 는 사용자 글이 둘 이상이거나 사용자가 넓혀 말한 것(「전부」 · 「통일」 · 「앞으로」 · 「지양」 · 「꼭」), 또는
  AGENTS · design_system 에 이미 있는 규칙이다. SHOULD 는 사용자가 한 번 말했거나 검수에서 「괜찮음」 으로 받은 꼴이다 —
  메모 없는 「괜찮음」 하나로는 SHOULD 까지다.
- **상태** — 확정 = 근거가 사용자 글 · 보드 선택 · 「괜찮음」 이거나 이미 시행 중인 규칙과 같다. 제안 = 한 사례에서 넓혔거나
  추정한 것이라 짝 질문을 달아 묻는 규칙(답 전에는 그 질문의 권장안으로 시행) — 이 판에는 없다. 폐기 = 뒤집힌 규칙 —
  지우지 않고 7장에 남긴다.
- **규칙 블록** — 머리(id · 이름) → 규칙 글 → 수준 · 범위 · 예외 · 판단(설계 · 검수 때 묻는 한 줄) · 그물(지금 지키는 시험 ·
  화면 확인 항목) · 그물 후보(5장) · 근거 · 지금 값(4장).
- **근거 꼬리표** — 「검수 <칸>」 = 사용자 검수표 칸의 메모, 「검수 「괜찮음」 <칸>」 = 메모 없이 받은 칸, 「… 결정 보드 …」 =
  보드에서 고른 선택지, 「확인 보드 AMB-nn (가)」 = 6장의 답, 「AGENTS n장」 · 「design_system」 = 기존 규칙 원문, 「귀납」 =
  여러 결과에서 추정, 「반영 기록」 · 「TODO 3장 기록」 = 반영한 사실. 괄호 안은 날짜이고, 끝의 「…」 는 사용자 원문 한 줄이다
  (줄인 자리는 …).
- **id** — `UI-<묶음>-nn` · `PRC-nn`. 한 번 쓴 id 는 다른 규칙에 다시 쓰지 않는다 — 폐기해도 번호는 비워 둔다.

## 2. 운영 — 규칙으로 설계 · 검수하는 차례

### 2-1. 개념

- **귀납(설계 원칙 도출)** — 검수 의견 · 결정 기록에서 되풀이된 꼴을 뽑아 규칙으로 올린다. 이 문서가 그렇게 만들어졌다.
- **휴리스틱 평가(규칙 기반 평가)** — 새 화면을 규칙 하나하나에 대 보고 통과 · 위반을 가른다. 규칙마다 단 「판단」 질문이 그
  도구다.
- **RFC 2119 강제 수준** — MUST · SHOULD · MAY(1-2).
- **수용 기준(acceptance criteria)** — 검수 한 칸이 통과하는 조건. 여기서는 「걸린 규칙 모두 통과, 또는 까닭을 적은 예외」.
- **그물** — 위반이 다시 들어오면 실패하는 자동 검사. 규칙마다 「그물」 · 「그물 후보」 로 적었다.
- **누수(escape)** — 규칙 판정은 통과였는데 사용자가 검수에서 고친 것. 규칙이 빠졌거나 틀렸다는 신호라 판마다 센다.
- **결정 기록(ADR 꼴)** — 규칙마다 근거 · 날짜 · 상태를 남기고, 물음과 답은 6장, 판의 변화는 8장에 적는다.

### 2-2. 차례

1. **설계** — 지시에 걸리는 규칙 id 와 그 판단 질문을 적는다(PRC-07). 규칙 밖 새 꼴이면 만들기 전에 선택지 + 권장 + 까닭으로
   묻는다(PRC-02).
2. **구현** — 그물이 있는 규칙은 시험이 지킨다. 새 꼴을 만들면 그 규칙의 그물 후보(5장)를 같은 변경에 세운다(PRC-01). 화면을
   바꿨으면 AppTest 로 진입 · 동작을 확인하는 시험을 둔다(AGENTS 9장).
3. **자체 검토** — 걸린 규칙마다 통과 · 위반 · 예외(까닭) 한 줄. 위반은 고친 뒤 같은 꼴 전체로 넓힌다(PRC-01). 꼴:

   ```text
   규칙 판정 — <변경 이름>
   UI-TXT-01 통과 · UI-NTF-02 통과 · UI-INP-07 예외(까닭: …)
   UI-LAY-01 위반 → 고침(찾은 3 · 고친 3 · 남긴 0) · 그물 tests/test_<…>.py
   ```

4. **사용자 검수** — 검수표에는 규칙 밖 새 꼴 · 규칙 판정이 애매한 칸 · 되돌리기 어려운 화면(저장 · 발행 · 삭제)만 올리고,
   칸마다 걸린 규칙 id 와 에이전트 판정을 붙인다. 규칙 안 항목은 고친 뒤 「규칙 판정 목록」 으로만 보고한다(PRC-07). 에이전트가
   정한 수치는 「제안 값」 으로 올려 「괜찮음」 이면 4장에 확정한다(PRC-03).
5. **되먹임** — 검수 의견을 셋으로 가른다: 규칙 안(위반 — 고치고 넓힌다) · 규칙 밖(새 규칙 후보 — 짝 질문을 달아 묻는다) ·
   규칙과 맞섬(규칙 고침 후보). 결함 · 오독 · 막힘 · 규칙 위반은 바로 고치고, 꾸밈 · 편의는 검수표로 묻는다(PRC-04). 답이
   오면 판을 올린다(PRC-08).
6. **재기** — 판마다 누수 수 · 규칙 밖 의견 수 · 남은 위반 후보 수를 센다. 누수가 줄면 검수표를 더 줄이고, 늘면 칸마다 올리는
   꼴로 되돌린다.

## 3. 규칙

### 3-1. UI-TXT — 화면 글 · 정보 밀도

화면에 무엇을 글로 두고 무엇을 걷는가.

#### UI-TXT-01 · 설명 문장을 늘 띄워 두지 않는다

화면(사이드바 상자 · 팝업 머리 · 판 바닥 · 캡션 · 본문 머리)에 사용법 · 동작 원리 · 보관 범위 · 저장 규칙 · 판정 범위를 풀어 쓴 설명 문장을 늘 띄워 두지 않는다. 눌러야 보이는 풍선(`help=`)과 Guide 로 옮긴 말은 둔다 — 금지는 늘 보이는 문장이다.

- 수준: MUST · 확정
- 범위: 모든 화면 · 팝업 · 사이드바 · 떠 있는 판 · 모듈 화면
- 예외: 입력 곁 오류 · 거부(폼 검증, UI-NTF-03) / 값 · 표지 — 목록 구획의 빈 결과 · 점검 화면의 결론 포함(UI-TXT-04) / 누르기 전에 알아야 하는 되돌릴 수 없는 결과(UI-NTF-09) / 화면을 그리지 못하는 오류(UI-NTF-08).
- 판단: 이 글을 지우면 사용자가 무엇을 못 하게 되나? 답이 없으면 지우고, 있으면 UI-TXT-02 의 갈 곳 넷 가운데 어디로 갈지 먼저 본다.
- 그물: `tests/test_place_sentence_sites.py`(화면 글 문장 그물 — `st.caption` · `st.info` · `st.markdown` 의 서술형 문장 자리를 (파일, 함수)별 까닭 허용 목록과 맞댐, 미정리 수는 늘지 않음) · `tests/test_alert_center_assets.py::test_the_alarm_and_change_panels_carry_no_description_footer`(Alarm · 변경 판만) · `scripts/check_deploy_screens.py` period_popup · process_popup(조건 팝업 둘의 「설명 글 0줄」 — 배포 화면 확인 때)
- 그물 후보: 설정 팝업 「설명 글 0줄」
- 근거: 검수 alarm-02 · alarm-11 · home-19 · home-21 · home-u01(2026-11-03), Space 결정 보드 메모(2026-11-04), 조건 카드 · Guide 결정(2026-09-28), 확인 보드 AMB-01 (가) · AMB-02 (가)(2026-11-04) — 「저런식으로 인터페이스에 설명문구를 다는걸 지양하도록해」
- 지금 값: 없음

#### UI-TXT-02 · 걷은 말의 갈 곳은 넷

걷은 말은 갈 곳 넷 가운데 하나로 보낸다 — 사용법 · 규칙은 Guide, 칸 하나의 뜻은 그 칸 곁 풍선(`help=`), 상태 · 내역은 알림창 · Alarm, 할 수 있는지는 단추 상태(UI-INP-07). 풍선 · Guide 로 옮긴 말은 줄이지 않아도 된다. 고치는 곳을 가리키는 길 안내도 Guide · 풍선이 말하고, 걷은 자리에 바로 가기 단추를 새로 두지 않는다(UI-TXT-03).

- 수준: MUST · 확정
- 범위: 모든 화면 글
- 예외: 없음
- 판단: 걷은 말이 넷 가운데 어디에 남았나? 아무 데도 없다면 그 말은 정말 필요 없었나?
- 그물: `tests/test_page_guide.py`(Guide 원문 · 설정 사전) · 화면 시험 `test_*_guide_carries_*`(옮긴 핵심 문구 대조)
- 그물 후보: 옮긴 곳 시험 — 걷은 글의 핵심 낱말이 Guide md 나 `help=` 에 있는지(`test_*_guide_carries_*` 틀)
- 근거: 조건 카드 · Guide 결정(2026-09-28), Space 결정 보드 메모(2026-11-04), 반영 기록(2026-11-04), 확인 보드 AMB-01 (가)(2026-11-04)
- 지금 값: 없음

#### UI-TXT-03 · 값 요약 · 길 안내 문장을 머리에 달지 않는다 — 바로 가기도 두지 않는다

팝업 · 조건 칸 · 카드 머리에 지금 값의 요약이나 「○○ → ○○ 에서 고칩니다」 식 길 안내 문장을 쓰지 않는다. 길 안내 글은 걷기만 하고 그 자리에 바로 가기(링크 · 단추)를 새로 두지 않는다 — 고치는 곳은 Guide 나 그 칸의 풍선이 말한다. 같은 화면 안을 가리키는 안내(「이름은 … 표에서 바로 고칩니다」)도 같다.

- 수준: MUST · 확정
- 범위: 모든 팝업 · 조건 칸 · 설정 화면 · 읽기 전용 값 카드
- 예외: 그 칸이 보이는 값 자체(「라벨 · 값」 줄 · 「선택 n / N」 — UI-TXT-04)는 요약 문장이 아니다.
- 판단: 이 글은 값을 보이나, 길을 말하나? 길이면 지우고 바로 가기도 세우지 않는다 — 고치는 곳은 Guide · 풍선이 말한다.
- 그물: `tests/test_home_settings_pointers.py`(없어진 HOME 「Preference」 탭을 가리키는 한 꼴) · `tests/test_place_sentence_sites.py`(「… 에서 정합니다」 꼴 길 안내 문장 — 화면 글 문장 그물)
- 그물 후보: 없음
- 근거: 검수 home-20 · home-21(2026-11-03), 확인 보드 AMB-06 (나)(2026-11-04) — 「[… 판정 기준은 HOME 설정 → Preference 에서 정합니다.] 이런 설명들 제거」
- 지금 값: 없음

#### UI-TXT-04 · 자리 글은 값 · 표지만, 내역 · 설명은 옮긴다

화면 자리에 늘 두는 글은 값과 표지뿐이다. 값 = 지금 보고 있는 것(「라벨 · 값」 · 버전 줄 · 「선택 n / N」, 목록 구획의 빈 결과 「…이 없습니다」, 점검 화면의 결론), 표지 = 조건이 있을 때만 서는 낱말 한두 개 · 점 · 배지 · 칩. 조건의 내역(건수 · 목록 · 까닭)은 알림창 · Alarm 으로(머리 변경 칩 · 판은 내역을 모으는 정한 자리 — UI-LAY-04), 설명(하는 법 · 규칙 · 범위 · 길 안내)은 Guide · 풍선으로 보낸다. 빈 결과 · 점검 결론은 자리에 평문 한 줄(`st.caption`)로 두고 초록 성공 상자(`st.success`)를 쓰지 않으며 하는 법 · 길 안내를 붙이지 않는다. 숨은 데이터 안내(표에 보이지 않는 저장분 · 그리지 않는 항목)는 칸 머리 표지 + 풍선으로 둔다.

- 수준: MUST · 확정
- 범위: 사이드바 · 머리 띠 · 탭 줄 · 칩 줄 · 팝업 머리 · 본문 캡션 · 목록 구획 · 점검 화면
- 예외: 입력 곁 거부 · 오류(UI-NTF-03), 화면을 못 그리는 오류(UI-NTF-08).
- 판단: 이 글은 값 · 표지 · 내역 · 설명 가운데 무엇인가? 값 · 표지가 아니면 자리에서 뺀다 — 서술어가 없어도 건수 · 목록을 늘어놓으면 내역이다.
- 그물: `tests/test_place_text_lines.py`(빈 결과 · 점검 결론 네 화면 — 성공 상자 없음 · 평문 한 줄, 숨은 공정 칸 머리 풍선) · `tests/test_place_sentence_sites.py`(자리 글 까닭 사전 — 값 · 표지 · 빈 결과 · 입력 곁 거부 · 못 그리는 오류 · 미정리, `tests/source_sites.py`) · 문장으로 끝나지 않는 내역 줄은 판단 질문으로 본다
- 그물 후보: 표지 글자 수 상한
- 근거: 검수 「괜찮음」 home-15 · 16 · 23(2026-11-03), 알림 결정 보드 D5(2026-11-03), Space 결정 보드 메모(2026-11-04), 귀납, 확인 보드 AMB-02 (가)(2026-11-04)

#### UI-TXT-05 · 늘 참인 기본 맥락은 붙이지 않는다

사용자에게 늘 참인 기본 맥락(쓰는 곳 · 환경 · 운영 중임)은 화면 글 · 기능 이름에 붙이지 않고, 표지는 예외 상태에만 단다 — 낱말을 뺄 때는 문장을 다시 맞춘다.

#### UI-TXT-06 · 머리 · 판 · 칩 글은 미리 정한 짧은 글

머리 띠 · 변경 판 · 칩 · 알림 짧은 글은 화면별 짧은 글 표 한 곳에서 꺼내 쓰고, 화면이 그 자리에서 글을 짓지 않는다. 화면의 새 상태를 알리려고 머리에 새 칩 · 새 줄을 세우지 않고 변경 칩 · 판 안 한 줄로 더한다 — 좁으면 줄이고 합친다(UI-ACC-02).

#### UI-NTF-01 · 알림은 한 꼴 · 한 길

앱의 알림은 한 꼴 · 한 길이다 — 오른쪽 아래 알림창(맨 앞에 단계 글자, 누름을 막지 않고 대화상자 위에 뜸)으로 띄우고 머리 Alarm 에 쌓는다. 화면마다 제 꼴의 경고 상자 · 토스트 · 초록 결과 상자를 따로 만들지 않는다.

- 범위: 모든 화면 · 팝업 · 모듈 화면의 알림

#### UI-NTF-02 · 상태 경고는 자리에 세우지 않는다

상태 경고(조건이 남아 있는 동안의 경고)는 화면 자리에 세우지 않는다 — 그 한 줄 요약도 남기지 않고, 내용(지문)이 바뀔 때만 알림창 한 번 + Alarm 기록, 조건이 사라지면 「해소」 로 닫는다. 저장 · 공식 지정 · 발행 뒤 한 번 내는 경고(남은 Capa 계산 오류 · 소요대수에 들지 않은 수요)는 상태가 아니라 동작 뒤 사건이다 — UI-NTF-03 을 따른다.

- 수준: MUST · 확정
- 범위: 모든 화면 · 사이드바 · 팝업의 상태 경고

- 그물: `tests/test_alert_sites.py` · `tests/test_state_alerts.py` · `tests/test_area_b_alerts.py` · `tests/test_place_sentence_sites.py`(상태 문장 자리 — 화면 글 문장 그물) · `tests/test_withdrawn_warning_alerts.py`(걷은 경고 ↔ 알림 코드)
- 그물 후보: 없음

#### UI-NTF-03 · 동작 결과는 알림창 하나로

동작 결과(저장 · 적용 · 불러옴 · 발행 · 삭제)는 알림창 하나로만 알리고, 누른 자리 곁에는 그 자리에서 고칠 입력이 있는 오류 · 거부만 남긴다. 동작이 끝났고 그 자리에 고칠 입력이 없는 경고 · 거부(HOME 주요 Case 칩을 누른 뒤의 「읽지 못했습니다」 · 「지정이 그사이 바뀌어 불러오지 않았습니다」, 사이드바 리비전 저장 · 복제 · 공식 지정 · 월 머지 · 연도 Shift · BigDataQuery 등록 · 자동 갱신 「지금 실행」 뒤 남은 Capa 계산 오류 · 소요대수에 들지 않은 수요, 그 사이 빠진 대상이라 아무것도 하지 않은 누름 등)는 알림창 · Alarm 에만 사건으로 낸다(`queue_flash(…, popup_only=True)` — 해소 줄은 없다). 같은 글을 두 자리에 띄우지 않는다.

- 수준: MUST · 확정
- 범위: 모든 쓰기 단추 · 팝업 · 편집표
- 예외: 「바뀐 것이 없습니다」 여섯 곳은 버튼 곁 그대로(빠른 둘째 누름 안내와 얽힘 — 2026-11-03 답).
- 판단: 사용자가 그 자리에서 고쳐야 할 것이 있나? 없으면 알림창.
- 그물: `tests/test_flash_messages.py::test_a_success_is_sent_to_the_alert_popup_and_not_drawn_beside_the_button` 외 · `tests/test_notice_form_sites.py`(초록 결과 상자 · 토스트 직접 부름 허용 목록)
- 그물 후보: 없음

### 7-3. 규칙으로 올리지 않은 것

한 번의 결정이라 규칙이 아니라 그 규칙의 사례로만 쓴다.

- 생산 진도 자리 화면에 샘플 페이지 셋을 임시로 세운 것 — UI-LAY-10 의 사례.
- Space 도형 한 팔만 늘이기 · 반전 — 기능 요청이고, 방향은 UI-INP-01(파워포인트 관례)이다.
- HOME 설정 팝업의 다섯 탭 묶음(비교 · 주요 Case / 판정 기준 / 선행 · 보정 / 공지 · 표시 / Past Data) — UI-LAY-06 의 결과물.
- 알림 결정 보드 D6 「서버 분석 기록은 usage-log 1단계와 함께」 — 운영 차례라 화면 규칙이 아니다.
- 세부 수치(알림창 450ms · 반복 창 60초 · 600px · 8 · 15초 · 3칸 · Summary ± 단추 18px · 계산기 폭 · Space 테마 색) — 4장 지금 값.
- 「바뀐 것이 없습니다」 여섯 곳은 버튼 곁(2026-11-03) — UI-NTF-03 의 예외.
- Alarm 로그 복사에서 딸린 표를 빼고 CSV 로 내려받게 한 것 — UI-NTF-04 의 세부.
- Space 결정 보드 「공식과 견주기는 호기 자리만」 — 이번 범위다(PRC-04 · AMB-09 (가)). 같은 보드의 「필요할 때 사이드바를
  굴림」 은 원칙이 됐다(UI-CON-03).

    해소 줄 없음)이고, 공식 지정의 계산 검사는 단추를 잠그지 않고 누른 회차에 거부하며, 까닭 풍선은 실제로 잠근 단추에만 단다.
    화면 글 문장 그물은 차례로 짝지은 부름 · 까닭의 꼴도 맞댄다(값 · 표지 · 빈 결과는 평문 — `st.info` 상자 아님, 빈 결과는
    결론 꼴, 하는 법 · 길 안내 꼬리 없음 — `st.write` · `st.text` · `st.html` 도 센다). 문서 그물은 `경로::이름` 시험이 실제로
    있는지 · (나) 두 답의 핵심 문구 · 장 사이 빈 줄을 본다.
  - **대신 정한 것(사용자 확인 대기 — PRC-02)**: UI-TXT-04 SHOULD → MUST 는 사용자 답이 아니라 이 판을 쓴 앱 세션이 정했다
    (AMB-02 (가)는 기준을 답했고 수준은 묻지 않았다). MUST 면 미정리 자리(화면 글 문장 그물 `UNSETTLED_SITES`)가 모두 MUST 위반이라
    PRC-04 · AMB-17 (가)로 「바로 고칠」 대상이 된다 — 권장은 MUST 그대로 두고 미정리는 화면 묶음마다 판을 나눠 줄이는 것이다.
