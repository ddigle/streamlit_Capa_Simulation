# 가용설비 현황 개편 — Codex 후보

현재 화면은 서로 다른 질문의 답을 한꺼번에 펼쳐 필요한 표를 먼저 찾아야 한다.
이 후보는 **질문 → 조건 → 보기** 순서로 고르고 한 결과 영역에서 답을 확인하도록 바꾼다.
계산식과 설비 저장 계약은 유지한다. 브라우저 검증은 2026-09-22, Codex 전용 8503에서 했다.

## 질문을 찾는 자리

| 기존에 확인하던 내용 | 새 동선 |
|---|---|
| 총대수·가용대수·비가동대수·가용률, 주차별 추이 | Main → 가용대수 → 추이 |
| 공정소분류별 대수 | Main → 가용대수 → 공정별 |
| 호기의 생애주기 상태 분포와 목록 | Main → 호기 현황 → 상태 분포 또는 목록 |
| 호기별 생애주기 일정 | Main → 호기 현황 → 생애주기 일정 |
| 선택일의 비가동 호기 | Main → 비가동 호기 → 기준일·공정 선택 |
| Qual 계획·확정·완료·지연과 대상 호기 | Main → Qual 일정 |
| Static과 Dynamic 가용대수 차이·분해·확보율 비교 | Static/Dynamic → 질문·보기 선택 |
| 공정별 Cut-off 입력·저장 | Preference → Cut-off |
| 세 입력표의 붙여넣기·검증·편집·불변 리비전 저장 | RawData → 입력표·작업 선택 |

동시에 펼치던 차트와 표를 선택형으로 접는다. 같은 수치를 다른 모양으로 겹쳐 그리던
부분을 덜어내며, 기존 질문에 대한 진입점은 남긴다. 비가동 호기는 선택한 **기준일의 상태**를
답한다. 월중 한 번이라도 비가동이었던 호기를 모으는 새로운 집계는 이 후보에 넣지 않는다.

## 입력 경험과 보존할 경계

RawData의 Import는 입력표를 고른 뒤 붙여넣기 또는 CSV 파일 업로드로 가져와
**변경 미리보기 → 확인 후 리비전 저장** 두 단계로 끝낸다. 따로 편집본에 적용한 다음
다시 저장 버튼을 찾는 단계를 없앴다. 직접 편집과 저장 이력은 같은 작업 영역의 별도 탭이다.
기존 보유대수는 공정·분류, 호기 마스터는 호기,
비가동 일정은 호기·유형·시작일로 추가·대체한다. 화면에서 좁힌 행과 감춘 컬럼도 최종
저장에는 보존하며, 세 입력표는 계속 하나의 불변 리비전으로 저장한다. 미리보기 이후
입력이나 편집본이 달라지면 변경 내용을 다시 확인하도록 한다. 빈 DB의 실제 편집본은
비워 두고 합성 샘플은 조회에만 사용한다. Cut-off는 기존대로
별도 전체 교체 저장이다. HOME·B/N의 Static 기준과 물리 대수·환산대수 구분은 바꾸지 않는다.

## 검증 및 채택 근거

실제 브라우저에서 빈 DB의 첫 행동, 「10월 Die Attach의 비가동 호기」 탐색,
30행 붙여넣기부터 저장까지를 확인했다. AppTest는 두 DB를 임시 폴더로 격리해 탭 왕복,
선택일·필터, Import 전후 draft, 저장 후 재조회와 숨긴 데이터 보존을 검증한다.
계산 서비스의 기존 회귀 테스트와 Ruff·mypy·전체 pytest·worktree 격리 검사는 별도로 수행한다.

- 빈 DB: Main의 첫 안내에서 `설비 데이터 입력` 한 번으로 RawData에 진입했다.
- 비가동 조회: 질문 선택 → 기준일 입력 → 공정 검색·선택의 **3개 조건 조작**으로
  10월 15일 Die Attach의 합성 샘플 1대를 확인했다. 별도 확인 버튼은 없다.
- 30행 Import: TSV 붙여넣기 → 미리보기 → 저장의 **3개 논리 조작**으로 신규 30행을
  확인하고 r1을 저장했다. 저장본은 기존 보유 0행·호기 30행·비가동 0행이었다.
  조작 수에서 페이지 진입·스크롤과 클릭·타이핑의 세부 분할은 제외했다.
- 왕복·오류 복구: Space 페이지 왕복 후 Main 질문·기준일·공정이 유지됐다.
  잘못된 헤더 오류 뒤 CSV 30행을 업로드하여 대체 30행 미리보기로 복구했다.
  화면 자료는 Git 제외 경로 `data/output/equipment-ui-*.png`에 둔다.
- 같은 합성 데모 입력의 변경 전후 기본 집계는 총 796대·가용 794대·비가동 2대·
  가용률 99.7%로 같았다. 업무 상수가 아닌 이 데모의 관측값이다.
- 의존성: 추가 없음. 현재 Streamlit의 파일 업로드·폼·탭·편집기를 사용한다. 추가 휠·전이
  의존성·설치 크기는 모두 0이다. 외부 그리드 교체는 이번 후보에서 채택하지 않았다.
  입력 동선과 검증·저장 피드백을 먼저 개선하며, 사내 파일 입력이 막히면 기존 Excel
  표 붙여넣기를 그대로 사용한다.
  [AG Grid의 클립보드 기능](https://www.ag-grid.com/javascript-data-grid/clipboard/)은
  Enterprise 기능이며, [기본 편집기의 붙여넣기](https://docs.streamlit.io/develop/concepts/design/dataframes#copy-and-paste-support)는
  컬럼 타입에 맞지 않는 셀을 건너뛸 수 있다. 따라서 대량 입력은 원문 전체를 검증하는
  붙여넣기·CSV 경로로 두고, 셀 단위 수정은 기본 편집기를 유지했다.
- 자동 검증: Ruff 포맷·린트, mypy, 전체 pytest, 작업 폴더 격리 검사 통과.
  기존 예상 실패 2건은 유지했다. 기준일 경계·단일 결과·탭 왕복·30행 원자 저장·다른 표와
  과거 리비전 보존·미리보기 변경 후 재검토·오류 복구를 검사했다. 후속 입력·월 축 변경은
  해당 테스트와 실제 화면으로 다시 확인했다. 1100px 다크 화면에서도 조건은 잘림 없이 줄바꿈된다.
