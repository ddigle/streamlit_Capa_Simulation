# 지시서 — 사이드바 상자를 한 양식으로 (claude)

**브랜치**: `cand/사이드바통일/claude` · **포트**: 8502 · **기준**: `origin/main`

**시작 조건**: 충족됐다. `cand/시나리오합치기/codex` 가 `7adfa69` 로 합쳐졌다 —
그쪽이 `app.py` 의 조회기간 블록(`min_month`·`max_month` 를 실제 월 범위로 넓힘)을
고쳤으므로, **이 과제는 그 뒤의 `app.py` 에서 출발해야** 같은 줄을 두 번 고치지 않는다.

---

## 1. 무엇이 문제인가

사용자 말:

> Capa Chatbot, 시나리오 관리, Static Capa, Dynamic Capa 까지는 페이지 버튼 양식이
> 통일되어 있고, 하위 페이지가 있는 경우에는 확장되게끔 되어 있는데, **시나리오·리비전과
> 조회기간, B/N 집계 공정, 관리 페이지에도 평소에 같은 양식으로 접혀 있다가, 하위가
> 아래로 펼쳐지면서 기존 메뉴를 사용할 수 있게끔** 양식을 통일하고 싶다.

지금 사이드바에 두 종류가 섞여 있다.

| | 양식 | 어디서 그리나 |
|---|---|---|
| Capa Chatbot · 시나리오 관리 | 테두리 상자 + `page_link` 한 줄 | `app.py:119` |
| Static Capa · Dynamic Capa | **`st.expander`** — 지금 보는 페이지가 든 그룹만 펴짐 | `app.py:125` |
| **시나리오·리비전** | 테두리 상자 + 항상 펼친 컨트롤 | `components/scenario_status.py:46` |
| **조회기간** | 테두리 상자 + 항상 펼친 피커 | `app.py:138` |
| **B/N 집계 공정** | 상자 (HOME 이 그린다) | `sidebar_status.py` · HOME |
| **관리** | 테두리 **없는** 상자 + 캡션 | `app.py:174` |

아래 넷이 **항상 펼쳐져 있어** 사이드바가 길고, 위의 접히는 양식과 따로 논다.

---

## 2. 무엇을 만드나

**아래 넷도 `st.expander` 로 접는다.** 평소에는 제목 한 줄이고, 펴면 지금 컨트롤이
그대로 나온다. 위의 페이지 그룹과 **같은 양식**으로 보여야 한다.

- 시나리오·리비전
- 조회기간
- B/N 집계 공정
- 관리

### 접었을 때 무엇이 보이나 — **사용자가 정해 줬다**

사용자 말:

> 조회기간과 시나리오·리비전은 **접더라도 제목 옆에 붙여 놓은 적용 날짜와 공식버전
> 정보가 보이게끔만** 해 달라. 접은 상태에서 지금 시나리오와 리비전을 모두 보이게
> 하려면 접힌 제목 줄에 담을 것이 너무 많아진다.

그러므로 **지금 제목 옆에 있는 그 두 조각만** 접힌 줄에 남긴다.

| 상자 | 접었을 때 보일 것 |
|---|---|
| 시나리오·리비전 | 공식버전 배지 (`공식 v3`) |
| 조회기간 | 적용 기간 (`적용 · 26.07–27.12`) |

**시나리오 이름·리비전 이름은 접힌 줄에 넣지 않는다.** 길어서 줄이 넘친다.

### 무엇을 언제 펴나

페이지 그룹은 「지금 보는 페이지가 든 그룹만 편다」는 규칙이 있다(`app.py:123`).
**컨트롤 상자에는 그 규칙을 그대로 쓸 수 없다** — 어느 페이지에서나 쓰는 것들이다.

후보가 정하되 아래를 고려한다.

- **B/N 집계 공정은 HOME 에서만 쓴다.** HOME 에서만 펴는 것이 자연스러울 수 있다.
- **관리는 거의 안 쓴다.** 접어 두기 좋은 자리다.
- 사용자가 편 상태를 **세션 동안 기억할지**도 정한다.

무엇을 고르든 **왜 그렇게 했는지 커밋에 적는다.**

## 2-1. 같이 고칠 것 둘

### ① 배지·적용기간을 **우측정렬**한다

사용자 말:

> 지금 그 공식버전 마크와 적용 기간이 사이드바 제목에 붙어 있는데, 이걸 **우측정렬**해
> 달라. 마크·적용기간만 우측정렬하고 **페이지명은 다른 양식과 동일하게** 배치.

지금은 제목 바로 옆에 붙어 있어(`_render_title_row` 의 `horizontal` 컨테이너, `app.py`
의 조회기간 줄도 같은 꼴) 제목 길이에 따라 배지 자리가 흔들린다.

- 제목은 **왼쪽 끝**에 — 다른 상자의 페이지명과 같은 자리.
- 배지·적용기간은 **오른쪽 끝**으로.
- 접었을 때도 같은 자리를 지킨다. `st.expander` 의 제목은 문자열 하나라 그 안에서
  좌우로 밀 수 없을 수 있다 — 그러면 CSS 로 민다(`sidebar_style.py`).

### ② 시나리오·리비전 아이콘을 바꾼다

사용자 말:

> 시나리오·리비전에 적용 중인 아이콘이 시나리오 관리랑 동일해서 다른 적절한 아이콘으로.

확인했다. **둘 다 `:material/database:` 다.**

- `navigation.py:60` — `시나리오 관리` 페이지
- `components/scenario_status.py:192` — 사이드바 `시나리오·리비전` 상자

사이드바에 같은 아이콘이 둘 나란히 서서 어느 것이 페이지이고 어느 것이 컨트롤인지
구분되지 않는다. **바꿀 쪽은 사이드바 상자(`scenario_status.py`)다** — `시나리오 관리`
는 페이지라 다른 페이지들과 아이콘 규칙을 공유한다.

무엇으로 바꿀지는 후보가 고른다. 「지금 무엇을 보고 있나」를 뜻하는 것이 맞다 —
`database` 는 저장소를 뜻해 관리 페이지 쪽에 더 어울린다. 고른 이유를 커밋에 적어라.

## 3. 반드시 지킬 것

- **접어도 배지가 보여야 한다.** 2장 표의 두 조각이다. 그 이상은 넣지 않는다.
- **`관리` 의 테두리 없음은 뜻이 있다.** `app.py:172` 가 적어 둔 대로 관리는 계산 흐름
  밖이라 다른 상자와 나란히 서면 같은 층위로 읽힌다. 양식을 통일하면서 그 구분을 어떻게
  살릴지 정한다 — 없애도 되지만 그 판단을 적는다.
- **맨 아래 순서를 깨지 마라.** 관리 상자는 CSS `order` 로 맨 아래에 고정돼 있다
  (`sidebar_style.py`). 페이지가 자기 사이드바 요소를 더하는 것이 `navigation.run()`
  안이라 파이썬 차례로는 뒤에 둘 수 없기 때문이다.
- **B/N 집계 공정은 HOME 이 그린다.** `app.py` 가 아니라 HOME 쪽을 고쳐야 한다.
- 지금 CSS 훅(`st-key-…_box`)이 상자 key 에 걸려 있다. `st.expander` 도 `key` 를
  받으므로 클래스가 유지되지만, **`container` 와 `expander` 는 DOM 이 달라** 선택자가
  헛돌 수 있다. `sidebar_style.py` 를 같이 고친다.
- 계산·저장 동작을 바꾸지 않는다. **자리만 바꾸는 일이다.**
