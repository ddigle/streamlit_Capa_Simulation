# 지시서 — 가용설비 세 표의 「현재 데이터」를 내려받게 (claude)

**브랜치**: `cand/설비CSV내보내기/claude` · **포트**: 8502 · **기준**: `origin/main`(`dce2f6e`)

**마이그레이션 번호**: 홀수(`0029`)가 네 몫이다. 다만 **이 과제에는 마이그레이션이 필요
없어 보인다** — 내보내기는 읽기만 한다. 필요하다고 판단되면 먼저 그 판단을 적는다.

---

## 1. 무엇이 문제인가

사용자 말:

> 가용설비 현황 페이지에서 호기마스터, 기존보유대수, 비가동일정 CSV로 다운받을 때
> **기존에 입력된 데이터들을 다운받는 기능이 지금 없지?**

없다. `components/equipment_data_workspace.py:589-613` 의 「입력 양식과 작성 기준」 안에
버튼이 셋 있지만 전부 **빈 양식**이다. `services/equipment_csv.py` 의
`equipment_csv_template()`·`baseline_csv_template()`·`downtime_csv_template()`(`:53`·`:74`·
`:119`)이 `SAMPLE_*` 리터럴로 **예시 한 줄짜리 프레임을 새로 만들어** 내보낸다. 지금
입력된 데이터는 보지 않는다.

**기준 정보 페이지는 다르다.** 거기는 `reference_edit_csv_bytes(data, key_columns)` 로
**현재 표 그대로**를 내보내서 Excel 에서 고치고 다시 붙여넣는 왕복이 된다. 설비 쪽만 그
왕복이 반쪽이다 — 올리는 길만 있고 내려받는 길이 없다.

그래서 셋이 막혀 있다. **백업**(리비전 저장 전에 손에 쥘 것이 없다), **일괄 수정**
(60여 호기를 Excel 에서 고치려면 먼저 손으로 옮겨 적어야 한다), **사내 리뷰 첨부**
(지금 무엇이 들어 있는지 보낼 방법이 없다).

---

## 2. 무엇을 만드나

**세 표 각각에 「현재 데이터」 내려받기를 붙인다.** 양식 버튼은 그대로 두고 나란히 선다 —
빈 양식이 필요한 경우(처음 채울 때)와 현재 데이터가 필요한 경우(고칠 때)가 다르다.

- 내보낸 CSV 를 **그대로 다시 붙여넣으면 통과해야 한다.** 이것이 이 기능의 합격선이다.
  지금 읽는 쪽은 `read_equipment_csv`·`read_baseline_csv`·`read_downtime_csv`
  (`equipment_csv.py:137`·`:141`·`:153`)이고 각각 `EQUIPMENT_COLUMNS`·`BASELINE_COLUMNS`·
  `DOWNTIME_COLUMNS` 를 요구한다. **컬럼 이름·차례가 그 계약과 같아야 한다.**
- **무엇을 내보낼 것인가** — 저장된 리비전인가, 지금 편집 중인 버퍼인가. 워크스페이스는
  `BUFFER_KEY` 에 세 프레임을 들고 있고(`equipment_data_workspace.py:553-556`) 저장 전
  편집이 거기 쌓인다. 후보가 정하고 **화면 문구로 어느 쪽인지 말한다** — 사용자가
  「지금 보는 것」과 다른 것을 받으면 조용한 혼란이 된다.
- **파일 이름에 무엇을 담을지** 정한다. 기준 정보 쪽은 `RQ_UPEH_<시작>_<끝>.csv` 처럼
  범위를 담는다. 설비 세 표는 월 범위가 없으니 다른 근거(리비전·날짜)가 필요하다.
- 데이터가 **비어 있을 때** 어떻게 할지 정한다. 헤더만 있는 CSV 를 주는 것과 버튼을
  막는 것 중 무엇이 나은지 판단하고 적는다.

## 3. 반드시 지킬 것

- **실데이터가 나가는 길이다.** 이 CSV 에는 실제 호기 번호·공정명이 들어간다.
  `data/output/` 같은 저장소 안에 파일을 쓰지 않는다 — 브라우저 다운로드로만 나간다
  (`render_csv_download` 가 이미 그 방식이다).
- **Excel 이 값을 숫자로 바꾸는 것**을 조심한다. 기준 정보 쪽은 `="…"` 로 묶어 내보내는
  장치가 있다(`services/reference_csv.py` 의 `_guard_excel_text`). 호기 번호나 공정명에
  `4.00E+02` 처럼 읽히는 값이 있을 수 있다 — **실제로 그런 값이 있는지 확인하고**, 있으면
  같은 방식을 쓰거나 왜 필요 없는지 적는다.
- **읽기만 한다.** 내보내기가 버퍼나 저장 상태를 건드리면 안 된다.
- **셋을 같은 모양으로.** 한 표만 다른 방식이면 다음 사람이 어느 쪽이 정답인지 모른다.
- 기존 양식 버튼·붙여넣기·직접 편집 경로를 그대로 둔다.

---

## 4. 확인할 것

- **왕복을 실제로 해 본다.** 8502 에서 세 표를 각각 내려받아 → 값 하나를 고쳐 →
  붙여넣기로 적용 → 그 값이 들어갔는지 본다. **세 표 모두.** 이것이 이 과제의 핵심 검증이고
  자동 검사로는 절반만 잡힌다.
- 내려받은 CSV 를 **고치지 않고 그대로** 붙여넣어도 통과하는지 본다(무변경 왕복).
- Excel 로 한 번 열었다 저장한 뒤 붙여넣어도 통과하는지 본다 — 실제로 사용자가 하는 일이다.
- 빈 상태(데이터 없음)에서 버튼이 어떻게 동작하는지 본다.
- 검증 5종(`ruff format --check`·`ruff check`·`mypy`·`pytest`·`check_worktree_isolation.py`).
