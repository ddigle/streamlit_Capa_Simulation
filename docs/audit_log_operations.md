# 접속 · 작업 기록 운영

이 문서는 C-DEP 운영 서버의 「접속 · 작업 기록」(Admin Area 넷째 탭)을 **사람이 어떻게 쓰는지** 적는다. 코드 규칙은
`AGENTS.md` 5장 40 · 3장 `src/capa_simulation/audit/`, 통합인증 쪽(사건 대응표 · 점검자 환경변수)은 `docs/sso_setup.md`,
버킷 쪽(접두사 · 권한 · 수명 규칙)은 `docs/objectstore_setup.md` 이다. 여기 적은 주기 · 기준 값은 **권장 시작값**이다 —
사내 정보보호 규정이 정한 값이 있으면 그 값으로 바꾸고, 바꾼 값은 이 문서와 내부관리계획에 함께 적는다.

지금 판(1판)에 있는 것과 없는 것을 먼저 가른다.

| 있음(1판) | 아직 없음(2판 — 1판을 사내에서 한 달 돌린 뒤) |
|---|---|
| 접속 사건 · 관리자 행위 · 데이터 작업 기록, 운영 도구 조각 | 내려받기 기록 · 화면 진입 기록 · 기록 열람 기록 |
| 「요약 · 기록」 두 보기, 사이드바 「기록 조건」 | 「점검」 보기와 「점검 기록」 단추, 사슬 검증 화면 |
| 알림 `AD-12`(보관 안 됨) · `AD-13`(늦게 온 조각) | 이상 징후 알림(반복 실패 · 근무 외 관리 · 대량 내려받기 · 점검 지남) |
| 버킷 일별 묶음 · 미러 · 해시 사슬 | 감사 표 「전체 행 CSV」(기록되는 내보내기) |

---

## 1. 역할

| 역할 | 누가 | 하는 일 | 못 하는 일 |
|---|---|---|---|
| 앱 관리자 | `CAPA_ACCESS_ADMINS` 의 사람 | 매일 훑기, 알림 1차 조치, 접속 명단 관리 | 감사 기록 고치기 · 지우기 · 끄기(앱에 그 기능이 없다) |
| 점검자 | `CAPA_AUDIT_VIEWERS` 의 사람 — 권장은 팀장이나 정보보호 담당 1명 | 월 1회 점검 | 앱 설정 · 명단 바꾸기(관리 칸이 서지 않는다) |
| 저장소 관리자 | 버킷을 가진 IT · 플랫폼 | 버킷 수명 규칙(`audit/` 3년 + 30일), 버전 관리 · Object Lock(지원하면) | — |
| 사용자 | 접속 명단에 든 사람 | — | 기록을 보지 못한다 |

- 점검자도 앱에 들어오려면 접속 명단에 있어야 한다. 점검자 목록은 C-DEP 환경변수로만 바뀐다 — 관리자가 화면에서
  점검자를 고르지 못하게 한 것이다(직무 분리).
- 점검자를 둘 수 없으면 앱 관리자가 스스로 점검한다(「자기 점검」). 그때는 분기에 한 번 팀장이 함께 기록 보기를 본다.

## 2. 매일(1분) — 앱 관리자

1. 어느 화면에서든 오른쪽 아래 알림창 · 머리 `Alarm` 에 `AD-12` · `AD-13` 이 떴는지 본다. 떴으면 6장대로 한다.
2. Admin Area › 「접속 · 작업 기록」 › 요약의 오늘 값 칸 넷(접속자 · 로그인 실패 · 명단 밖 · 작업)을 본다.
   - 접속자 수가 평소와 비슷한지 본다.
   - 로그인 실패 · 명단 밖이 0 이 아니면 기록 보기에서 사람별로 본다(사이드바 「기록 조건」 › 사람).
3. 공식 발행 · 삭제 · 명단 변경이 있었다면 내가 한 일인지, 요청받은 일인지 떠올린다.

## 3. 월 1회(15분) — 점검자, 매월 10일까지

1. 사이드바 「기록 조건」 기간을 **지난달 1일 – 말일**로 놓는다.
2. 요약 보기의 날짜별 표를 훑는다. 휴일 · 새벽에 값이 있는 날을 찾는다.
   - 빈칸은 그날 조건에 맞는 기록이 없다는 뜻이다. 아무도 들어오지 않은 날도 빈칸이라 빈칸만으로 기록기가 멈췄다고
     적지 않는다(기록기 · 올리기 멈춤은 `AD-12` 가 알린다). 사람 · 갈래 · 결과를 고르면 표도 그 조건으로 센다.
   - 기간이 지난달이면 위 오늘 값 칸 넷은 「—」 다(오늘을 읽지 않았다).
3. 기록 보기에서 차례로 본다(사이드바 「사건 갈래」 로 좁힌다).
   - **관리** 갈래 전부 — 명단 추가 · 삭제, 토큰 넣기, 지금 올리기, 세대 되돌리기 · 이관 · 사본 받기 · 정리(운영 도구 —
     행위자는 OS 사용자 이름, 미검증), 자동 갱신 설정 · 수동 실행. 앱 관리자 자신의 행위도 여기에 있다.
   - **작업** › 삭제 · 공식 발행 — 누가 언제 했는지.
   - **결과** › 실패 · 거부 · 결과 모름 — 같은 계정의 되풀이, 모르는 계정.
4. 점검 결과(대상 달 · 확인한 것 · 의견 · 조치)를 남긴다. 1판에는 「점검 기록」 단추가 없으므로 사내 결재 · 메일 같은
   **앱 밖** 기록에 남긴다.

## 4. 분기 1회 — 앱 관리자 + 점검자

- **접속 명단 다시 보기** — 퇴사 · 전보 · 업무가 바뀐 사람을 뺀다(빼는 것도 기록된다).
- **열람 권한 다시 보기** — `CAPA_ACCESS_ADMINS` · `CAPA_AUDIT_VIEWERS` 의 사람이 아직 맞는지 본다.
- **보관 상태 보기** — 사용자가 사내 PC 별도 창에서 `sync_object_storage.py audit-list --month YYYY-MM` 을 쳐서 날짜마다
  조각 · 일별 파일 **수**만 확인한다(사람 값은 찍지 않는다). 날짜가 비면 6장 `AD-12` 를 본다.

## 5. CI/CD 앞

CI/CD 를 누르기 전에 Admin Area 「DB 동기화」 의 **지금 올리기** 를 누른다 — 감사 기록부터 올린다. 그 칸의
「감사 미전송」 이 0 이 되면 그 pod 의 기록이 버킷에 다 들어간 것이다. 0 이 아닌 채 pod 이 바뀌면 남은 몫은 다음
기동이 `/project/data` 가 남아 있을 때만 올린다.

- 「감사 미전송」 은 아직 올리지 않은 줄에 **아직 열린 시간 묶음**(로그인 전 실패 · 명단 밖 되풀이 · 로그인 갱신 ·
  DB 올림 건수 — 정시 뒤 한 줄씩)을 더한 수다. **지금 올리기** 는 그 묶음을 앞당겨 한 줄씩(`partial`) 닫아 함께
  올리고, DB 를 올린 뒤 그 몫까지 한 번 더 올린다. 같은 시간의 나머지는 정시 뒤 한 줄이 더 온다(요약 표는 줄마다
  더한다).

## 6. 알림과 조치

| 알림 | 뜻 | 조치 |
|---|---|---|
| `AD-12` | 기록이 버킷에 보관되지 않음 — 동기화 아님(`managed` 아님) · 올리기 없음(동기화 일꾼이 감사 할 일 없이 섰음) · 올리기 30분 넘게 밀림 · 큐 넘침 · 시계 차이 60초 넘음 | 「DB 동기화」 칸을 보고 **지금 올리기** 를 누른다. 「올리기 없음」 은 이것으로 풀리지 않으니 곧바로 사외에 리뷰로 알린다(그대로 CI/CD 하면 그 pod 의 기록이 사라진다). 계속되면 사외에 리뷰로 알린다 |
| `AD-13` | 14일보다 늦게 온 기록 조각 — 일별 묶음 밖 | 고치려 하지 않는다. 날짜를 점검 결과에 적고 저장소 관리자 · 보안 담당에 알린다 |

사람이 훑을 때의 기준(권장 시작값 — 1판은 알림이 없다. 한 달 운영한 뒤 오탐을 보고 조정한다).

| 볼 것 | 기준 | 조치 |
|---|---|---|
| 로그인 실패 반복 | 같은 계정 10분 안에 5회, 또는 로그인 전 실패 한 시간 50회 | 당사자에게 확인한다. 모르는 일이면 ADFS 잠금 · 보안 담당에 알린다 |
| 명단 밖 반복 | 같은 계정 하루 3회 이상 | 접속 요청인지 확인한다. 필요하면 명단에 넣는다 |
| 근무 외 관리자 행위 | 평일 20:00 – 07:00(KST) · 주말의 관리 갈래 | 내가 한 일이 아니면 곧바로 `CAPA_ACCESS_ADMINS` 를 점검하고 보안 담당에 알린다 |
| 삭제 몰림 | 한 사람이 하루 시나리오 삭제 3건 이상 | 의도인지 확인한다. 실수면 버킷 세대(최신 5세대 + 7일)에서 되살릴 수 있는지 본다 |

## 7. 사건 때(조사)

- 기간 · 사람 · 갈래로 좁혀 기록 보기에서 시간순으로 본다. 작업 줄의 대상 id(시나리오 · 리비전 · 설비 시나리오 리비전)로
  그 화면에서 내용을 견준다 — 리비전 · 공식 발행은 추가만 되므로 내용이 남아 있다.
- 400일보다 오래된 기록은 버킷에만 있다. 필요하면 사외에 리뷰로 요청한다(1판에는 받는 도구가 없다).
- 기록 보기의 loginid 는 실제 사람이다 — 리뷰 문서에 옮기지 않는다(옮길 것은 수와 날짜뿐).

## 8. 기록되지 않는 것

서버가 알 수 없는 동작이라 감사 기록에 남지 않는다.

- 표 위 도구 막대(`st.dataframe`)의 CSV 내려받기 · 클립보드 복사, 알림창 CSV · Space 편집기 CSV(브라우저가 만든다).
  1판에는 앱의 내려받기 단추 기록도 없다(2판).
- 인쇄(Print 단추 · 브라우저 인쇄) · 화면 캡처.
- 모듈 화면 안의 작업(모듈 창구에 로그인 사용자를 넘기는 길이 아직 없다).
- 사내 PC · WebIDE 앱의 모든 동작, C-DEP 에서 통합인증이 꺼진 동안(`AD-02`) — 「누가」 가 없다.

## 9. 내부관리계획에 적을 값(권장 시작값)

| 항목 | 값 |
|---|---|
| 기록 항목 | 계정(loginid) · 접속일시(UTC 저장, KST 표시) · 접속지(칸만 있음 — 사내에서 실제 사용자 IP 가 실리는 자리를 확인한 뒤 켠다) · 처리한 정보주체(명단 변경의 대상 loginid) · 수행업무(사건 · 대상 id · 결과) |
| 보관 | 3년(버킷 수명 규칙 `audit/` 3년 + 30일). 기간 전에 지우지 않고, 법적 보류가 걸리면 정리를 멈춘다 |
| 위변조 방지 | 새 객체로만 쓰기 · 줄마다 해시 사슬 · 일별 manifest 가 앞 manifest 해시를 이음 · 앱에 고치기 · 지우기 · 끄기 기능 없음 |
| 열람자 | 앱 관리자 · 점검자(`CAPA_AUDIT_VIEWERS`)만 |
| 점검 주기 · 방법 | 매일 1분 훑기(2장) · 월 1회 점검(3장) · 분기 명단 재검토(4장) |
| 사후조치 | 6장 표 |
| 시각 | 서버 시계가 사내 NTP 에 맞춰지는지는 사내 확인 거리다. 첫 조각에서 버킷 시각과 60초 넘게 다르면 `AD-12` |
