# 과제 정의 — 시나리오 월 머지와 연도 Shift

**과제명**: `시나리오합치기`
**브랜치**: `cand/시나리오합치기/codex`
**기준**: `origin/main`
**담당**: codex 후보 한 쪽. 경쟁이 아니다.

---

## 0. 왜 필요한가

사용자 말 그대로 옮긴다.

> BDQ 로 다운받는 DB 기반 시나리오는 종종 **28년 데이터인데 27년으로 기록**되는 경우가
> 있다. 그리고 어떤 시나리오는 **27년까지만 검토**되어 있고, **28~30년 검토 시나리오는
> 다른 케이스로 분리**되어 있기도 하다. 이걸 사용자가 **생산계획년월 기준으로 머지**할
> 수 있는 인터페이스를 구성하고 싶다.

**기능은 둘이고 서로 독립이다.** 하나가 막혀도 다른 하나는 쓸 수 있어야 한다.

| | 기능 | 답하는 것 |
|---|---|---|
| A | **월 머지** | 27년까지의 A 와 28~30년의 B 를 한 시나리오로 |
| B | **연도 Shift** | 1년 늦게 찍힌 시나리오를 통째로 밀기 |

---

## 1. 먼저 알아야 할 제약 — 표 16개 중 4개는 월이 없다

`ref_data` 를 직접 세어 확인했다(2026-09-23).

| | 표 |
|---|---|
| 월 축 **있음** 12개 | `rq_eqp_avbl` `rq_eqp_lent` `rq_eqp_own` `rq_lot_ratio` `rq_pkg_plan` `rq_reqb` `rq_run_day` `rq_run_rate` `rq_upeh` `rq_vital` `rq_wf_ratio` `rq_yld` |
| 월 축 **없음** 4개 | `rq_chip_eq`(Density) `rq_chip_qty` `rq_module` `rq_display_order` |

**월이 없는 넷은 월로 자를 수 없다.** 그래서 두 기능 모두 이 넷을 특별히 다룬다.

## 2. 기능 A — 월 머지

### 무엇을 하나

사용자가 **베이스 시나리오**와 **더할 시나리오**를 고르고, 더할 쪽에서 **가져올 월
범위**를 정하면, 둘을 합친 **새 시나리오**를 만든다.

### 사용자 결정 (이미 정해짐 — 바꾸지 말 것)

1. **월 없는 표 넷은 베이스 것을 그대로 쓴다.** 더할 쪽 것은 버린다.
   **다만 두 쪽이 서로 다르면 화면이 그 사실과 행 수를 반드시 알린다** — 조용히
   버리면 Density 가 다른 줄 모르고 쓰게 된다.
2. **결과는 새 시나리오로 저장한다.** 원본 둘은 건드리지 않는다.

### 설계에서 정할 것 (후보가 정한다)

- 월이 **겹칠 때** 어떻게 하나. 아래 넷이 선택지다.

  1. **사용자가 고르게 한다** — 겹치는 월을 보여 주고 어느 쪽을 쓸지 그 자리에서 고른다.
  2. 베이스를 이기게 한다.
  3. 더할 쪽을 이기게 한다.
  4. 막는다.

  **1번이 실제 쓰임에 가깝다.** 27년까지 검토된 시나리오와 28~30년 시나리오를 합치는데
  27년이 양쪽에 다 있고, 어느 쪽 27년을 쓸지는 그때그때 다르다. 막으면 그 판단을 화면
  밖에서 하라는 뜻이 된다.

  > **2026-09-23 정정.** 처음 이 절에 1번을 빠뜨리고 2~4번만 적었다. 후보가 4번을 골라
  > 구현했는데 선택이 틀린 것이 아니라 **선택지가 모자랐다.** 정의서에서 선택지를 나열할
  > 때는 「사용자가 그 자리에서 고른다」를 빠뜨리지 않는다 — 규칙을 미리 정하는 것과
  > 쓰는 사람이 고르는 것은 다른 답이고, 업무 판단이 갈리는 자리에서는 대개 뒤가 맞다.
- 월 범위를 어떻게 고르게 할지(범위 두 칸 / 월 목록 / 「나머지 전부」).
- 새 시나리오의 이름과 메모에 **무엇이 어디서 왔는지** 어떻게 남길지.

### 반드시 지킬 것

- 합친 뒤 **12개 표의 월 축이 서로 어긋나지 않아야 한다.** 한 표만 28년이 없으면
  그 달의 계산이 조용히 비거나 예외가 난다. 저장 전에 검사하고 어긋나면 막는다.
- 새 시나리오는 기존 경로(`create_scenario`)로 만든다. 스키마를 바꾸지 않는다.

## 3. 기능 B — 연도 Shift

### 무엇을 하나

시나리오 하나를 잡고 **연 단위로** `생산계획년월` 을 민다.

### 사용자 결정 (이미 정해짐 — 바꾸지 말 것)

1. **연 단위만이다.** 실제로 연 단위로 밀리는 경우만 생겼다. 개월 단위 이동은 만들지
   않는다.
2. **몇 년을 밀지 고를 수 있어야 한다.** `+1년` 하나로 고정하지 않는다.
3. **어긋남은 사람만 안다.** 그 DB 에 적재한 사용자가 아는 것이고 **DB 에는 근거가
   남지 않는다.** 그러므로 **기계가 판별하려 들지 마라** — 화면에서 사용자가 직접
   고르게 한다. 자동 검출·추천을 만들지 않는다.

### 반드시 지킬 것

- **월 없는 표 넷은 밀지 않는다.** 밀 월이 없다.
- 민 결과가 유효한 `YYYYMM` 이어야 한다(`services/frame_contracts.normalize_month_column`
  이 쓰는 규칙과 같은 범위). 넘치면 저장 전에 막는다.
- **원본을 덮지 않는다.** 기능 A 와 같이 새 시나리오로 저장한다 — 잘못 민 것을
  되돌릴 방법이 그것뿐이다.
- 화면이 **밀기 전후 월 범위를 나란히 보여 준다**(`2701~2712 → 2801~2812`). 누르기
  전에 무엇이 되는지 보여야 한다.

## 4. 건드리지 말 것

- **계산 산식을 바꾸지 않는다.** 이 과제는 시나리오를 만드는 일이다.
- **스키마를 바꾸지 않는다.** 필요하다고 판단되면 **만들기 전에 사용자에게 묻는다**
  (마이그레이션은 되돌릴 수 없다. codex 는 짝수 번호).
- 리비전은 append-only 다. 과거 리비전을 고치지 않는다.
- `HANDOFF.md`·`README.md` 는 건드리지 않는다 — 통합 담당 몫이다.
- 진행 중인 다른 과제와 겹치지 않게: **설비 화면(`available_equipment_status`·
  `equipment_*`)을 건드리지 마라.** 같은 시기에 다른 후보가 그쪽을 고치고 있다.

---

## 5. 반드시 지킬 것

- **화면을 실제로 띄워 보고 만든다.** codex 포트는 **8503**. 다른 번호를 쓰지 마라.
- 올리기 전에 자기 폴더에서 검증 5종을 돌린다(ruff format·check, mypy, pytest,
  `scripts/check_worktree_isolation.py`).
- **두 기능을 각각 되돌릴 수 있게 커밋을 나눈다.** 하나가 문제여도 다른 하나는 남는다.
- 결과를 한 장으로 설명하는 글을 커밋에 남긴다 — 무엇을 어떻게 정했고, 월이 겹칠 때
  어떻게 했고, 월 없는 표를 어떻게 알렸는지.

---

## 6. 스스로 판단하지 말고 물어볼 것

- 스키마를 바꿔야 한다고 판단될 때.
- 월이 겹치는 규칙이 데이터에 따라 갈릴 때.
- 「월 축 없는 표가 다르다」를 **막을지 알리기만 할지** 실제 데이터를 보고 애매할 때.

같은 질문을 사용자가 두 번 답하지 않게, 물을 것을 모아서 한 번에 묻는다.
